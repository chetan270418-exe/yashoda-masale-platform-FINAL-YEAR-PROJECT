# ai-services

**This directory is intentionally empty of source code.**

The AI subsystem lives in [`../backend/app/ai/`](../backend/app/ai/), inside the
FastAPI application, because it has to run in the same process as the business
data it reasons about:

| Concern | Location |
|---|---|
| LLM adapter interface, mock and live providers | `backend/app/ai/llm_adapter.py` |
| Forecasting models, chronological evaluation, MASE, rolling-origin backtest | `backend/app/ai/forecasting/` |
| RAG retrieval and citation validation | `backend/app/ai/rag/` |
| Whitelisted tools, order drafts, agent query | `backend/app/ai/tools.py` |
| AI endpoints, rate limiting, draft approval | `backend/app/ai/router.py` |
| Approved knowledge base | `backend/app/ai/rag/knowledge_base/` |

## Why there is no duplicated copy here

An earlier iteration of this project carried a second, standalone copy of the
forecasting, RAG, LLM and agent code in this directory. Two copies of the same
logic drift apart, and the drift is invisible until one of them is wrong.

That copy was removed in commit `019de43` and the single implementation in
`backend/app/ai/` is the one the application actually serves. This directory is
kept as a placeholder so the repository layout stays stable, and it is the
natural home if a genuinely separate AI service is ever needed - for example a
Python service that is deployed and scaled independently of the API.

## What replaces it

- The M7 forecast evaluation report is generated by
  `backend/scripts/generate_forecast_evaluation_report.py` and written to
  [`../docs/forecast-evaluation/`](../docs/forecast-evaluation/).
- The knowledge base files that the RAG assistant answers from live in
  `backend/app/ai/rag/knowledge_base/`.
