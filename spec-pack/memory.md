## 1. Project in one paragraph
**Yashoda SpiceChain AI** is a web-first platform for the spice business Yashoda Masale. It records raw-material receipt, production batches, quality release, warehouse stock with FEFO, dealer/distributor and consumer orders, and QR batch traceability. A business AI layer adds forecasting, reorder and expiry-risk suggestions, a RAG assistant, a dealer reorder agent and natural-language analytics. It is a Diploma (Computer Engineering) final-year project with a 4-member team and a 24-week plan.

## 4. Glossary
- **Batch:** one production run with a unique code, dates and quality status.
- **FEFO:** First-Expired, First-Out stock picking.
- **Lot:** a received quantity of a raw material.
- **Reservation:** stock held for an order but not yet dispatched.
- **Ledger:** append-only list of stock movements.
- **RAG:** the AI retrieves approved documents before answering.
- **Tool (AI):** a safe, whitelisted function the AI may ask the server to run.
- **Synthetic data:** generated demo data, not real business records.
- **Baseline:** a simple forecast used to check whether the model adds value.
- **MAE / RMSE / MAPE:** forecast error measures.

## 6. Known issues and gotchas
- Tests run on SQLite locally (PostgreSQL only in CI). FOR UPDATE, CHECK constraints and Alembic migrations are only fully tested in CI.
- JSONB columns use `.with_variant(JSONB, "postgresql")` for SQLite compat.
- Reservation functions take a `commit` flag. `commit=False` means the CALLER owns the transaction: the function flushes only, never commits, and never rolls the caller's transaction back. `reserve_order` allocates every line item with `commit=False` and commits once, so a multi-line order is all-or-nothing (B4).
- `reserve_order` processes line items in `variant_id` order on purpose. Line-item row locks are now held until the final commit, so a stable global lock order is what stops two concurrent orders with opposite line order from deadlocking. Do not remove that sort.
- An approved AI order draft whose stock cannot be reserved stays in `open` status by design. The response carries `reservation_status` and `reservation_message`, and `APPROVE_DRAFT_RESERVATION_FAILED` is written to the audit log. Never swallow the reservation error there: a silent failure hides an unfulfillable order.
- `black` is the project formatter, not `ruff format`. CI runs `ruff check .`, `black --check .` and `pytest -v` against PostgreSQL.
- Batch statuses are lowercase snake_case and must match `ProductionBatch.status == "released"` exactly, because the FEFO query and the dispatch check compare that literal. The legacy `hold` and `recalled` values no longer exist anywhere: migration 0007 maps them to `on_hold` and the ORM CHECK constraint now lists exactly the canonical values, so the ORM and the migrated database agree. Do not reintroduce a legacy value.
- The public traceability payload is assembled field by field. Adding a field to `ProductionBatch` or `Product` must never change what the public page returns; extend the response model explicitly.
- The conftest builds the test schema with `Base.metadata.create_all`, not with Alembic, so the tests do not exercise the migrations. Run `alembic upgrade head` against a real PostgreSQL database before believing a migration works.
